# 백암초 방과후 통합 관리

백암초 본교와 수정분교장의 방과후학교 업무를 위한 GitHub Pages 시연 사이트입니다. 1단계는 가상 강사 목록과 경력 조회를 제공합니다. 실제 강사·학생 개인정보, 증빙자료, 비밀번호, API 키는 공개 저장소에 올리지 마세요.

## 파일 안내

- `index.html` — 대시보드, 메뉴, 강사 목록과 경력 상세 화면
- `style.css` — 기존 색상과 레이아웃, PC·모바일 화면
- `script.js` — 메뉴 이동, 부분 이름 검색, 학년도·학교·프로그램 필터, 강사 상세 화면
- `demo-data.js` — 학교, 강사 ID, 가상 계약 및 활동 이력
- `README.md` — 실행과 배포 안내

## 내 컴퓨터에서 확인

저장소에서 **Code → Download ZIP**을 선택하고 압축을 풉니다. `index.html`을 브라우저에서 엽니다. 별도의 설치나 빌드 과정 없이 실행할 수 있습니다.

1. **강사 관리**에서 `가람`을 입력합니다. 이름이 같은 강사 두 명을 ID와 담당 프로그램으로 구분할 수 있습니다.
2. **강사 경력관리**에서 `가람`, 2025학년도, 수정분교장, 합주를 선택합니다. 경력 1건이 표시됩니다.
3. 결과의 이름을 누릅니다. 해당 강사의 전체 학년도 및 양쪽 학교 경력이 표시됩니다. 계약기간, 실제 활동기간과 확인된 강의시간은 각각 표시되며, 미확인 항목에는 `미확인`이 표시됩니다.
4. **검색 결과로** 돌아가면 선택한 검색 조건이 유지됩니다. **검색 조건 초기화**를 누르면 전체 경력이 표시됩니다.

## 기존 GitHub Pages에 반영

1. GitHub의 [기존 저장소](https://github.com/Clock-00/after-school)에서 **Pull requests**를 열고 1단계 변경 제안을 선택합니다.
2. **Files changed**에서 변경 사항을 검토한 다음 **Merge pull request → Confirm merge**를 누릅니다. 초안 상태라면 먼저 **Ready for review**를 누릅니다.
3. **Actions**에서 Pages 배포 작업이 성공했는지 확인한 뒤 [기존 사이트](https://clock-00.github.io/after-school/)를 새로고침합니다. 배포 상태와 소스 설정은 **Settings → Pages**에서도 확인할 수 있습니다.

## 다음 단계 준비

학교에서 사용할 로그인 계정과 관리자·업무 담당자·승인 담당자의 권한 범위를 정합니다. 학교가 승인한 비공개 저장소와 서버에서 데이터 접근 권한을 검증할 방법을 검토하고, 증빙자료 접근 범위 및 보존·삭제 기준을 정합니다. 문서 발급 단계에는 학교 공식 양식과 전자결재 및 직인 반영 기준이 필요합니다.

## 2단계 역할별 로그인

GitHub Pages는 공개 시연용입니다. 업무용 Node.js 서버 주소에 접속하면 역할별 로그인 화면이 열리고, 로그인한 계정만 대시보드와 담당자 계정 화면을 열 수 있습니다.

1. Node.js 24 이상을 설치한 뒤 터미널에서 `cd _server`를 실행합니다.
2. 아래 명령으로 로컬 실습용 서버를 시작합니다. 예시 비밀번호는 실습에서만 사용하세요.

   ```sh
   LOCAL_DEMO=1 ADMIN_ID=school-admin ADMIN_PASSWORD=local-demo-password npm start
   ```

   Windows PowerShell에서는 아래와 같이 실행합니다.

   ```powershell
   $env:LOCAL_DEMO = "1"
   $env:ADMIN_ID = "school-admin"
   $env:ADMIN_PASSWORD = "local-demo-password"
   npm start
   ```

3. `http://127.0.0.1:3001`에서 관리자 역할을 선택하고 설정한 아이디와 비밀번호로 로그인합니다.
4. 대시보드의 **내 계정·로그아웃** 메뉴를 열어 업무 담당자 또는 승인 담당자 계정을 등록합니다. 시크릿 창에서 등록한 역할과 계정으로 로그인해 가상 경력을 확인합니다. 관리자 화면에서 접근을 해제하면 해당 계정의 로그인 세션도 종료됩니다.
5. `npm test`로 역할 검증, 계정 등록, 접근 해제 및 로그아웃을 확인할 수 있습니다.

### 운영 연결 준비

Node.js 서버를 운영할 때는 `APP_ORIGIN`(HTTPS 주소), `ADMIN_ID`, 최초 실행용 `ADMIN_PASSWORD`, 필요에 따라 `PORT`, `BIND_HOST`, `DATA_DIR`을 호스팅 환경에서 설정합니다. `DATA_DIR`은 서버의 비공개 영구 디스크에 둡니다. SQLite를 사용하는 구성은 서버 한 대에서 운영합니다.

이전 실습 DB를 이어 쓰려면 기존 관리자 이메일을 `ADMIN_ID`로 지정하고 최초 관리자 비밀번호를 설정합니다. 이전 로그인 링크와 세션은 만료 처리됩니다. 기존 담당자 계정은 관리자 화면에서 같은 아이디로 비밀번호를 등록할 수 있습니다.

서버에서 계정의 역할을 확인하며 세션은 8시간 동안 유효합니다. 로그인, 계정 등록, 접근 해제를 기록합니다. 실제 강사대장 입력·수정, 승인 및 PDF 출력, Supabase 연동은 후속 작업입니다.
