# 백암초 방과후 통합 관리

백암초 본교와 수정분교장의 방과후학교 업무를 위한 GitHub Pages 시연 사이트입니다. 1단계는 가상 강사 목록과 경력 조회를 제공합니다. 실제 강사·학생 개인정보, 증빙자료, 비밀번호, API 키는 공개 저장소에 올리지 마세요.

## 파일 안내

- `index.html` — 대시보드, 메뉴, 강사 목록과 경력 상세 화면
- `style.css` — 기존 색상과 레이아웃, PC·모바일 화면
- `script.js` — 메뉴 이동, 부분 이름 검색, 학년도·학교·프로그램 필터, 강사 상세 화면
- `demo-data.js` — 학교, 강사 ID, 가상 계약 및 활동 이력
- `README.md` — 실행과 배포 안내

## 내 컴퓨터에서 확인

저장소에서 **Code → Download ZIP**을 선택하고 압축을 풉니다. `index.html`을 브라우저에서 엽니다. 별도의 설치나 빌드 과정 없이 실행할 수 있습니다.

1. **강사 관리**에서 `가람`을 입력합니다. 이름이 같은 강사 두 명을 ID와 담당 프로그램으로 구분할 수 있습니다.
2. **강사 경력관리**에서 `가람`, 2025학년도, 수정분교장, 합주를 선택합니다. 경력 1건이 표시됩니다.
3. 결과의 이름을 누릅니다. 해당 강사의 전체 학년도 및 양쪽 학교 경력이 표시됩니다. 계약기간, 실제 활동기간과 확인된 강의시간은 각각 표시되며, 미확인 항목에는 `미확인`이 표시됩니다.
4. **검색 결과로** 돌아가면 선택한 검색 조건이 유지됩니다. **검색 조건 초기화**를 누르면 전체 경력이 표시됩니다.

## 기존 GitHub Pages에 반영

1. GitHub의 [기존 저장소](https://github.com/Clock-00/after-school)에서 **Pull requests**를 열고 1단계 변경 제안을 선택합니다.
2. **Files changed**에서 변경 사항을 검토한 다음 **Merge pull request → Confirm merge**를 누릅니다. 초안 상태라면 먼저 **Ready for review**를 누릅니다.
3. **Actions**에서 Pages 배포 작업이 성공했는지 확인한 뒤 [기존 사이트](https://clock-00.github.io/after-school/)를 새로고침합니다. 배포 상태와 소스 설정은 **Settings → Pages**에서도 확인할 수 있습니다.

## 다음 단계 준비

학교에서 사용할 로그인 계정과 관리자·업무 담당자·승인 담당자의 권한 범위를 정합니다. 학교가 승인한 비공개 저장소와 서버에서 데이터 접근 권한을 검증할 방법을 검토하고, 증빙자료 접근 범위 및 보존·삭제 기준을 정합니다. 문서 발급 단계에는 학교 공식 양식과 전자결재 및 직인 반영 기준이 필요합니다.

## 2단계 초대 로그인 실습

기존 GitHub Pages는 가상 데이터 시연용입니다. 초대 로그인 실습은 별도 Node.js 서버에서 실행합니다. 서버 코드와 환경 변수는 `_server` 아래에서 관리합니다.

1. Node.js 24 이상을 설치합니다.
2. 터미널에서 `cd _server`로 이동하고 `npm ci`를 실행합니다.
3. 아래 명령으로 가상 메일 모드를 시작합니다.

   ```sh
   DEMO_MAIL=1 ADMIN_EMAIL=admin@example.test npm start
   ```

   Windows PowerShell에서는 `$env:DEMO_MAIL = "1"`과 `$env:ADMIN_EMAIL = "admin@example.test"`을 실행한 뒤 `npm start`를 실행합니다.
4. 브라우저에서 `http://127.0.0.1:3001`을 열고 `admin@example.test`로 로그인 링크를 요청합니다. 터미널의 가상 메일 링크를 브라우저에 붙여 넣고 **이 링크로 로그인**을 누릅니다.
5. 관리자 화면에서 `staff@example.test`를 업무 담당자로 초대합니다. 그 사람의 가상 링크를 시크릿 창에서 열고 로그인해 가상 경력 조회와 역할을 확인합니다. 관리자 화면에서 **접근 해제**를 누르면 해당 로그인 세션과 미사용 링크가 취소됩니다.
6. `npm test`는 임시 데이터베이스에서 초대부터 접근 해제까지 검증합니다.

가상 메일 모드는 로컬 주소와 `example.test` 주소만 허용하며 실제 이메일을 보내지 않습니다. 실습 로그인 링크는 터미널에 표시됩니다.

### 운영 연결 준비

학교에서 승인한 Node.js 호스팅 및 SMTP 발송 서비스를 정한 뒤 별도 HTTPS 주소에 서버를 올립니다. 서버 환경 변수로 `APP_ORIGIN`(공개 HTTPS 주소), `ADMIN_EMAIL`(초기 관리자 이메일), `SMTP_URL`, `MAIL_FROM`, 필요에 따라 `PORT`, `BIND_HOST`, `DATA_DIR`을 설정합니다. `DATA_DIR`은 서버의 비공개 영구 디스크에 둡니다. SQLite를 사용하는 이 구성은 단일 서버 인스턴스에서 운영하도록 설계했습니다. SMTP 인증정보는 호스팅 서비스의 비밀 설정에 입력합니다.

일회용 링크는 15분, 세션은 8시간 동안 유효합니다. 서버에서 세션과 역할을 확인하며 로그인·초대·접근 해제를 기록합니다. 현재 서버는 로그인과 역할 분리를 검증하기 위한 가상 경력만 반환합니다. 실제 경력 등록·수정, 담당자별 업무 권한 검증, 운영 SMTP 발송 및 배포는 후속 작업입니다.
